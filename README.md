## What We Built

**DataMind Receipts** — Ask any natural-language question about real-world data and get a live, grounded answer backed by a SQL receipt.

No mocks. No cached results. Every answer comes from a **live Snowflake query**, explained by **Gemma 4**, and verified by code before it reaches you.

---

## How It Works

```
Your Question
     │
     ▼
[Gemma 4] Understand + Write SQL
     │
     ▼
[sqlglot] Validate (SELECT-only, allowlisted tables, LIMIT enforced)
     │
     ▼
[Snowflake] Execute live query (DM_READER role, read-only)
     │
     ▼
[Code] Compute flags (empty, anomaly, trend)
     │
     ▼
[Gemma 4] Write prose explanation from raw rows
     │
     ▼
[Code] Verify — numbers/entities in prose must match cells
     │
     ▼
[Code] Build receipt — tables, joins, filters from parsed SQL
     │
     ▼
Answer + Evidence + SQL Receipt
```

## Key Design Decisions

- **Gemma 4 does language only** — understand, write SQL, repair SQL, explain rows. Code does all computation, validation, and evidence selection.
- **SQL safety via `sqlglot`** — parse-based, not regex. Blocks INSERT, MERGE, DELETE, DROP, CALL, GRANT, COPY, multi-statement.
- **DM_READER role** — app only ever connects with SELECT-only credentials. `DM_LOADER` never in FastAPI.
- **Verifier is code** — numbers and entity names in prose are matched to actual query result cells. Mismatch → regenerate once → code-built sentence fallback.
- **Receipt is code** — extracted from parsed SQL AST, not generated by Gemma.
- **`config.yaml` is the single source of truth** — model names, temperatures, row limits. Nothing hardcoded.
